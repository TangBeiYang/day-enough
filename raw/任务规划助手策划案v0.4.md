# 用户能量管理 · 产品方案 v0.4



## 目标人群

高中时有老师和课表替你安排一切，任务是按每天的形式发布的，进入大学后这套外部结构突然消失了，任务都是按周，甚至按月发布。大多数大学生从来没有被教过怎么自己做任务决策，但他们又不是完全随性的人——他们会焦虑，想把事情做好，也认可规划是有用的，只是从来没有人告诉他们具体怎么做。

## 核心问题

大学生现在经常会因为自己每天做的东西到底该够不够而感到焦虑。 
现有的任务工具解决了"记住要做什么"，但没有解决"今天该做什么、做到什么程度"。用户每天面对的不是遗忘问题，而是决策问题。
这个决策问题有两层：
第一层是优先级判断。 任务很多，今天时间和精力有限，该先动哪个？现有工具给不出答案，用户只能靠感觉或者等DDL倒逼。
第二层是能量匹配。 即使知道该做什么，用户的状态每天不同，某些任务在状态差时根本推不动，强行安排只会加剧焦虑和拖延。

如果每天做的任务过少，可能需要在ddl到来前几天疯狂弥补；如果每天任务做得多，学生自己又会非常疲惫，会让学习效果变差。


## 一、任务录入

用户新建任务时填写以下信息：

### 基础信息
- 任务名称
- DDL（截止时间）
- 类型：一次性任务 / 周期性任务 / 长期项目

### 周期性任务扩展字段
（类型选"周期性"时展开）
- 重复频率：每天 / 每周（选星期几）/ 每两周 / 自定义
- 系统自动按频率生成该任务的每次实例，用户无需重复录入

### 重要程度评估
- **未完成的后果严重程度**：低 / 中 / 高
  → 硬核权重，直接决定推荐优先级
- **自己对这件事的意愿**：低 / 中 / 高
  → 软性参数，仅在能量不足需要取舍时作为辅助排序依据，不与后果严重度合并计算

> 设计说明：两者分开显示、分开使用，避免"愿意做的任务"总被排在前面，强化拖延行为。

### 能量评估
- 预计消耗能量：低 / 中 / 高

### 娱乐活动（可选，恢复能量）
- 活动名称
- 类型：碎片娱乐（刷视频等）/ 沉浸娱乐（游戏、电影等）/ 运动
- 计划时长
- 说明：娱乐是用户**提前规划**的恢复时间，系统据此预留能量空间；不要求用户事后汇报是否执行

## 二、新用户校准

首次使用时，完成一个约 2 分钟的简短问卷，生成个性化初始参数，替代冷启动均值：

1. 工作日平均每天有多少自由时间可支配？（滑条，0–10 小时）
2. 自我评价执行力怎样？（经常拖延 / 一般 / 比较自律）
3. 更习惯在哪个时间段做高难度任务？（上午 / 下午 / 晚上 / 没有规律）
4. 是否经常有特殊时期，比如期末或比赛冲刺？（是 / 否）

根据回答生成初始参数，系统后续持续自适应调整。

---

## 三、能量节律设置

校准问卷结束后可设置，或在"设置"中随时修改：

- 标记自己一天中的高效时段（上午 / 下午 / 晚上，可多选）
- 系统在每日推荐中，对每项任务附带建议完成时段，例如：
  - 「论文文献整理」→ 建议上午（高消耗，匹配高效时段）
  - 「回复邮件」→ 建议下午（低消耗，适合低效时段）

---

## 四、每日主界面

### 今日推荐任务列表
- 系统根据历史数据、能量参数、任务紧迫度与后果严重度生成推荐
- 每条任务附带建议完成时段（来自节律设置）
- 用户可手动调整顺序或跳过某条
- 设有换一换按钮，用户可点击此按钮重新生成一批任务（可以之后再做）

### 任务进度总览（可点开）
- 所有进行中任务的进度条，直观展示整体状态
- 长期项目显示两条进度条：**总进度** 与 **今日份额**，明确区分整体目标与当次任务

### 周视图（可切换）
- 显示本周每天的任务分布与 DDL 节点
- 帮助用户感知"按这个节奏，能不能赶上截止日期"
- 只读，不在此界面编辑任务

### 标记完成
- 完成任务后点击标记，进度条实时更新
- 白天的标记行为本身即为系统数据，不依赖晚上的问卷

---

## 五、提醒机制

### DDL 临近提醒
- 根据任务类型和消耗能量动态调整提前量（高消耗任务提前更多天提醒）

### 僵尸任务处理
当一项任务超过一定天数未被推荐执行或标记进展，系统弹出询问，给出三选一：
- **「还在等某些条件，暂时搁置」** → 标记为"等待中"，不计入能量计划，保留在列表
- **「还有效，继续推进」** → 重新纳入推荐
- **「已不需要了，删除」** → 删除任务

搁置中的任务会定期再次询问状态，避免永久沉底。

## 六、每日收尾问卷

### 触发时机
用户可自定义提醒时间（默认晚上 9 点），非强制填写。

### 问卷内容（控制在 1 分钟以内）
1. **未标记完成的任务**：每项一个滑条，拉到大概完成了多少（0–100%）
2. **今日疲惫程度**：滑条（→ 调整用户能量总量参数）
3. **比预期容易的长期任务**：多选（→ 系统降低其能量消耗估值）
4. **比预期难的长期任务**：多选（→ 系统提高其能量消耗估值）

### 填写激励
- 填完后立即显示「明日预览」：基于今天数据生成的明天推荐列表
- 连续填写天数显示为 streak 计数，形成习惯动力
- 填写率持续偏低时，系统提示"推荐准确度下降，因为数据不足"，让用户理解填写的意义

## 七、未填问卷的补救机制

问卷是辅助数据来源，不是系统运行的唯一支撑。即使用户完全不填，系统也能正常运行。

### 第一层：白天主动采集（问卷之外的数据）

| 行为信号 | 系统解读 |
|---|---|
| 任务被标记完成 | 最直接的完成度数据，无需问卷重复确认 |
| 打开应用的时间与频率 | 粗略推断用户今天是否在工作、状态如何 |
| 推荐任务被跳过或手动移除 | 视为该任务今天未执行的信号 |

### 第二层：未填问卷时的降级处理

| 缺失数据 | 系统处理方式 |
|---|---|
| 未标记任务的完成度 | 默认视为未完成，保留至下一天推荐，不猜测 |
| 今日疲惫程度 | 不更新能量参数，沿用近几天的滚动均值，单次缺失不影响整体参数 |
| 任务难易反馈 | 跳过本次修正，累积到下次填写时再调整 |

> 核心原则：**缺数据时保守处理，等下次有数据再修正。** 系统不因一次未填而失灵，只是这天的自适应学习步长为零。

### 第三层：次日轻量补救入口

用户次日打开应用时，若昨天未填问卷，在今日推荐上方显示一个可忽略的提示条：

> 「昨天有几件事没确认，花 30 秒补一下？」

补救内容极度精简，**只问一项**：昨天未标记完成的任务大概做了多少（滑条）。

疲惫度与难易反馈直接跳过——昨天的状态今天回忆已不准，强行填写反而引入噪声。补救条可直接忽略，不强制。

### 整体数据流向

```
白天标记行为（持续采集）
        ↓
晚上问卷（理想情况，填写更准确）
        ↓ 如未填写
系统降级：保守处理 + 参数暂不更新
        ↓
次日轻量补救条（可选，30 秒）
        ↓
系统正常运行，误差随时间收敛
```

## 八、系统自适应

系统在后台持续调整以下参数（算法细节待规划）：

- 用户每日可用能量总量
- 能量恢复速度（与娱乐计划和疲惫度数据联动）
- 各长期任务的能量消耗估值（根据"容易/难"反馈动态修正）
- 节律参数（若建议时段持续不匹配，触发重新校准提示）
