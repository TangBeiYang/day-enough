# 每日推荐算法：当前规则与后续观察

## 当前规则（v7）

- 生成或主动重排今天时，先在内存中试排未来至少 35 天、至多 60 天；只把今天的建议写入数据库。已保存的今日安排不会因刷新、任务变化或阶段变化自动改写；手动安排仍可超过预算。
- 未来每天的时间按「默认值 → 对应星期的设置 → 指定日期覆盖」取值；当天已保存的计划使用当时的今日预算。未来精力暂按「一般」估计，当天按用户所选精力限制高消耗任务。
- 试排包括当前可推进任务，以及由进行中的周期规则推算的未来实例。推算不创建任务或修改规则，只用于预留未来容量。已经创建的周/月实例仍可在计划完成日之前推荐。
- 根据真实截止、计划完成日和阶段目标的剩余工作量、剩余天数与各日容量计算建议份额。真实截止若再推迟就可能排不下，优先保障；阶段目标参与排序与份额。同一任务进入多个阶段时实际投入只占一次今日预算，同一段时间的进度可同时满足对应目标。
- 阶段「投入分钟」仅计算阶段开始日起的记录；阶段「完成任务」按原任务剩余工作量估计。完成原任务会完成其阶段目标。结束日期已过但仍追踪的目标继续参与推荐，不过不会随着过期天数无限抬高优先级。
- 无日期任务通常先安排 30 分钟；已至少一周、两周未推进的无日期任务逐级提高参与机会，两周仍未安排会提示复查。推荐尽量安排一段有意义的时间，容量或高消耗额度不足时可出现较短份额。
- 在未来试排中未能按截止日或阶段结束日完成的事项会显示预计缺口。这是基于当前剩余时间、未来预算与固定的未来「一般」精力所做的估算，不是完成保证。新任务或设置变化不会自动修改已保存的今日计划。

## 已验证场景

1. 今日有软计划日期，另一项明天真实截止而明天没有时间：优先安排真实截止。
2. 两日阶段目标、真实截止和每天周期任务争用容量：未来周期实例先占未来时间，阶段未完成的预计分钟以提醒展示。
3. 同一任务加入多个重叠阶段计划：工作时间不重复占用预算，目标进度共享。
4. 周内不同预算、指定日期覆盖、v7 JSON 导出/恢复及 v6 旧备份恢复。
5. 已有计划不会自动补充任务；重排仍保留完成、跳过和已投入部分；手动超预算依旧允许保存。

## 继续观察的边界

- 未来超过 60 天的目标按最多一年的容量估算近期建议份额，缺口预报暂限于 60 天试排窗口内；窗口外未显示提醒不表示一定来得及。
- 未来时间是用户设置的可用分钟估计，未来高消耗额度统一按「一般」估计；没有时段、疲劳恢复或自适应学习。
- 当前使用确定性的逐日分配规则；任务很多或多个目标同时争抢容量时，可能存在另一份更合适的安排。需要结合实际使用案例调整推荐份额和提醒措辞。
- 周/月未来实例按当前规则估计；如果之后暂停或改动规则，下次主动重排会使用新规则重新估算。
