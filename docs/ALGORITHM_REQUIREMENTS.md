# 每日推荐算法需求记录

这里记录新增功能对自动推荐的影响和验收场景；具体排序与分配公式以后集中设计。

## 当前行为

- 推荐从所有进行中、仍有剩余分钟的任务中按计划完成日期、截止日期、剩余工作量和后果排序，再逐项分配今日预算。
- 已记录投入先从今日预算扣除；高消耗任务受今日精力额度限制。无日期的普通任务通常先分配 30 分钟；周期本次尝试分配全部剩余时间。
- 已保存的今日安排不会因任务或阶段计划变化自动重排，用户主动生成、重排或自己安排才会改变它。

## 阶段计划带来的待设计问题

- 阶段目标在开始前、进行中、结束后，分别如何影响任务优先级？已创建任务当前立即参与推荐，不应被阶段开始日期当作隐藏任务的日期。
- 「完成整个任务」与「投入指定分钟」如何换算成每日建议份额？周六与周日可用时间不同、其中一天少做了时，如何调整后续份额？
- 阶段目标与更早的真实截止日期冲突时如何排序？总体容量不足时如何显示缺口，不要暗中超出预算。
- 同一任务属于多个重叠阶段计划时如何避免重复计算？阶段结束后继续追踪的目标，应如何和新的阶段目标共同排序？
- 「漏做不补做」的周期本次与阶段顺延语义冲突。本版禁止加入可顺延目标；未来若支持整个周期规则，需要单独定义每次实例的归属。
- 手动安排可以超过今日预算并保存，自动推荐仍遵守预算；阶段目标不应改变这两种模式各自的约束。

## 验收场景

1. 周末计划包含报告“完成整个任务”和阅读“投入 120 分钟”；周六只做了 20 分钟，周日应看到尚需推进的目标。
2. 周末计划结束后仍有未完成目标；日期与历史保留，后续投入继续累计，并提醒用户，但不自动改写已经保存的今日安排。
3. 周日截止的任务与下周结束的阶段目标同时存在；真实截止风险应被看见，阶段目标不能无条件挤掉更紧急的任务。
4. 一个高消耗任务位于多个阶段计划中；自动分配仍只占用一次今日时间与精力预算。
