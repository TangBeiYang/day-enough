# DayEnough

[English README](README.md)

一个个人任务规划工具，根据截止日期、可用时间和精力，帮你决定今天做什么，以及做到多少就够了。

DayEnough 是一个电脑优先的个人 Web 应用。数据统一保存在服务端，因此可以在不同电脑和操作系统中访问同一份任务与进度。

## 当前功能

- 用户名、密码登录；凭服务器邀请码注册新用户，每个账号的数据独立保存。
- 任务录入、编辑、完成、暂时搁置、继续做和删除。
- 截止日期可选，支持没有明确日期的个人任务。
- 普通任务支持可选计划日期；周期任务支持每天、每周指定星期和每月，每次独立记录进度。
- 记录预计剩余时间和实际投入时间。
- 根据截止日期、计划完成日、阶段目标、未来周期任务、可用时间及当前精力生成计划。
- 支持部分进度、完成今日份额、跳过、手动排序和主动重排。
- 今日计划保持稳定，完成后不会自动添加更多任务。
- 防止跨设备旧页面覆盖新数据和重复提交。
- 支持 JSON 导出/恢复及在线 SQLite 完整备份。
- 任务总览集中显示普通任务、当前周期任务和重复规则，直接修改本次或规则。

技术栈为 Python 3.11+、Flask、SQLite 和原生 HTML/CSS/JavaScript。无需前端构建，不依赖外部字体、AI API 或 CDN；生产环境使用 Linux 和 Gunicorn。

## 本地运行

在项目根目录执行（Linux/macOS；Windows 可使用 WSL）：

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
.venv/bin/flask --app day_enough set-password
.venv/bin/flask --app day_enough set-invite-code
.venv/bin/flask --app day_enough run --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000>。`set-password` 为 `owner` 设置至少 12 个字符的密码；现有个人任务自动属于此账号，用 `owner` 和原密码登录。`set-invite-code` 设置至少 12 个字符的邀请码，注册新用户时填写。密码和邀请码不会写入源代码；未设置邀请码时不能注册。

忘记密码可执行 `set-password --username 用户名`；默认重置 `owner`。原有登录会话将失效，任务数据保持不变。再次运行 `set-invite-code` 可立即换码；`disable-registration` 可暂停新注册。

Flask 开发服务器只用于本机试用。

## 部署到阿里云服务器

推荐让 Gunicorn 以普通服务用户运行应用，仅监听服务器本机的 `127.0.0.1:8000`；再由 Caddy 或服务器现有的 Nginx 提供公网 HTTPS。SQLite 数据放在服务器的独立目录，同一账号可从多台设备访问自己的数据。2 核 2GB 的个人服务器可先按仓库提供的单 worker、双线程配置试用。

部署前先确认服务器的 Linux 发行版、Python 版本、是否已有网站/反向代理、域名及其 DNS；如果本机已有任务，先从「设置」导出 JSON 备份。不要把 Flask 开发服务器或 Gunicorn 的 8000 端口直接暴露到公网。

1. 在服务器安装 Python 3.11+、`venv` 和 Git，获取仓库代码；创建独立服务用户及数据目录，并安装 `requirements.lock`。
2. 在服务器交互式设置个人密码，安装仓库提供的 systemd 服务文件，启动后先用服务器本机的 `curl http://127.0.0.1:8000/` 验证应用。
3. 将域名指向服务器，配置 Caddy 或复用现有 Nginx 转发到 `127.0.0.1:8000`；在阿里云安全组和服务器防火墙中放行所需的 80/443，验证 HTTPS 登录。无需开放 8000 端口。
4. 如需沿用本机任务，在服务器网站登录后用「设置 → 从备份恢复」导入先前的 JSON；再用另一台设备登录检查数据，并配置服务器备份。

每一步的命令、现有网站的处理方式、无域名时的临时 SSH 隧道、备份和更新办法见[完整 Linux 部署指南](docs/DEPLOYMENT.md)。在未确认服务器现状前，不要直接覆盖现有代理配置。

## 依赖文件怎么选

| 文件 | 用途 |
| --- | --- |
| `requirements.txt` | Flask 和 Gunicorn 的兼容版本范围，供维护依赖时使用。 |
| `requirements.lock` | 固定并已测试的生产依赖及间接依赖版本；本地使用和服务器部署均优先安装它。 |
| `requirements-dev.txt` | 引用 `requirements.txt`，再加入 pytest，供开发和后端测试使用。 |
| `requirements-browser.txt` | 引用开发依赖，再加入 Playwright，供可选的真实浏览器验收使用；还需单独安装 Chrome。 |

服务器正常运行只需 `requirements.lock`；不需要安装测试依赖或 Node。

## 每天怎么用

1. 添加任务，估计还需要多少分钟。截止日期可以留空；长期项目也可以写一个具体下一步。
2. 在「今天」设置可支配分钟与精力，可生成推荐计划，也可点「自己安排」挑选任务、填写分钟数并调整顺序。
3. 做完一部分时使用「记一部分」；完成推荐份额时使用「完成今日份额」。
4. 如果实际难度不同，在任务列表中修正剩余时间估计。
5. 当前份额全部处理后就可以收工。新增或修改任务不会自动增加今日安排，只有主动重排才会改变计划。

填写了截止日期的任务按上海时区当天结束处理。无截止日期任务仍会参与推荐，但不会产生截止风险提醒。精力是对高消耗任务的粗略约束，不是医学或生理量表。

重排会扣除当天已经记录的投入，并保留已完成或跳过的份额。跳过只影响当天。「设置」中可填写默认时间、每周各日时间和指定日期覆盖。推荐会在内存中试排最多 60 天，只保存今天的建议；未来精力按「一般」估计。截止和阶段缺口提示是估算，不是按时完成的保证。

自己安排也会保留已记录投入、已完成和跳过的份额。已投入与待做安排合计超过今日预算时，页面会明确提醒，但仍可按自己的判断保存；自动推荐继续遵守时间和精力预算。

## 计划日期与周期任务

计划完成日期表示「希望在这一天完成」，截止日期表示「最晚哪天完成」。所有已创建待办立即进入推荐候选，计划完成日越近优先级越高，超过计划完成日仍可继续。普通任务的两个日期均可留空；同时填写时，计划日期不能晚于截止日期。

新增时通过「普通任务／周期任务」按钮切换表单。周期表单依次设置重复频率、计划完成星期/每月日期、可选截止、开始日期与每次用时。每周可多选计划星期，本周每个所选星期对应一次任务，提前一起生成；截止星期取计划当天或之后最近的指定星期。每月可分别选择计划几号、截止几号或月末；截止早于计划日时顺延到下个月，当月不存在的日期取月末。实时摘要展示规则。精力、后果、下一步和每天任务的「计划当天必须完成」选项在「更多设置」中。

打开、刷新应用或执行操作时，提前生成当天、本周（周一至周日）或本月的实例，创建后即可参与推荐；完成本期不会提前追加下一期。明确设在未来的规则开始日期仍作为生效日期。无需后台定时服务。每次进度独立；默认过了截止日仍未完成才标记为漏做，没有截止则以本日/本周/本月结束为界，超过计划完成日仍可继续，保留已投入时间，不累计到下一次。选择「保留待办」则继续保留未完成的实例。

在「任务总览 → 周期规则与历史」管理规则和展开历史记录。编辑规则只影响尚未生成的实例，已有实例通过「编辑本次」单独调整。暂停停止生成新实例，已有实例保留；恢复不补生成暂停期间的任务。周期任务同样受时间和精力预算约束，已有今日计划需要主动重排才会加入新任务。

任务总览默认展示进行中的普通任务、当前周期任务、之前未完成且保留待办的周期任务，以及重复规则入口。「暂时搁置」保留进度，之后可继续做。删除任务需输入「删除」确认，并清除对应投入与每日安排记录；「删除本次」只影响该周期实例，刷新也不会再次生成；「删除重复规则」会连同历次任务和记录一起删除。如果只想停止以后重复并保留记录，使用「暂停重复」。

## 阶段计划

侧边栏的「阶段计划」适合规划周末、假期等几天内想做的事。填写名称与起止日期后，在详情页加入已有任务或新建普通任务。每项目标可以是「完成整个任务」，也可以是「从计划开始日起投入指定分钟」。这里与任务总览共用原任务和投入记录；移出目标或删除阶段计划不会删除原任务。

结束日期过后，未完成目标仍保留在计划中，并在「今天」显示提醒；之后记录的投入继续计入目标。可调整计划、结束追踪（停止提醒）或恢复追踪。设置为「漏做不补做」的周期本次不能加入可顺延目标，可改用保留待办的周期任务。主动生成或重排今天时，阶段目标会影响自动推荐；逾期目标仍可推进，但不会因为过期时间长而无限提高优先级。在「今天」点「自己安排」可筛选本计划任务，筛选不会取消原来勾选的份额。当前规则和预报边界见[算法说明](docs/ALGORITHM_REQUIREMENTS.md)。

## 数据与备份

默认数据目录是项目下的 `instance/`，其中包含 SQLite 数据库和会话签名密钥，已加入 `.gitignore`。可以用 `DAY_ENOUGH_DATA` 指定其他绝对路径。

- 日常备份：设置 → 导出 JSON。只包含当前账号的任务、周期规则、计划、投入记录和时间预算，不包含密码。
- 恢复：设置 → 从备份恢复。只替换当前账号的任务数据，应先导出当前状态。
- 服务器完整备份：

```bash
.venv/bin/flask --app day_enough backup backups/day-enough-2026-09-21.zip
```

备份命令使用 SQLite backup API，拒绝覆盖已有文件并校验数据库完整性；ZIP 包含主库及所有用户数据库。不要只复制运行中的主文件，也不要只备份主库；完整备份包含密码和邀请码哈希，应妥善保存。单用户历史安装仍可用 `.sqlite` 命令，但多用户必须使用 `.zip`。恢复 ZIP 时先停止服务，再将包内 `day-enough.sqlite` 和 `users/` 一起放回数据目录；详见[部署说明](docs/DEPLOYMENT.md)。

启动时会自动建立账号登记表，原有任务、计划、投入及设置继续属于 owner。升级前先备份，更新代码后重启应用。JSON 导出格式仍为 v7，仍支持恢复 v1–v6 备份；旧备份沿用原有每日默认时间。旧版应用不能用于多账号数据。

## 验证

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
node --check day_enough/static/app.js
```

可选的真实浏览器验收使用临时数据库，不会修改个人数据：

```bash
.venv/bin/pip install -r requirements-browser.txt
.venv/bin/python tests/browser_smoke.py
```

浏览器验收默认使用 `/usr/bin/google-chrome`，其他位置可通过 `CHROME_BIN` 指定。截图输出在已忽略的 `test-results/`。Node 只用于可选的 JavaScript 语法检查，应用本身不依赖 Node。
